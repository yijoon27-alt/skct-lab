# SKCT LAB

SKCT 창의수리·수열추리 개인용 CBT 학습 사이트. React + TypeScript + Vite + Tailwind CSS + Vitest. 제공 자료의 유형과 풀이 전략을 참고하여 직접 작성한 **기출형 모사 문항**이며 실제 기출 원문·공식 SKCT 서비스가 아닙니다.

## 온라인 접속

- 학습 사이트: https://yijoon27-alt.github.io/skct-lab/
- GitHub 저장소: https://github.com/yijoon27-alt/skct-lab
- 자동 검사·배포: https://github.com/yijoon27-alt/skct-lab/actions

Pages는 아래 자동 검사를 통과한 커밋만 배포합니다. 브라우저별 학습 기록은 JSON 백업으로 이동할 수 있습니다.

## 설치와 실행

Node.js 22.12 이상 또는 24 LTS를 사용합니다. 이 README가 있는 iCloud `SKCT/SKCT LAB` 폴더에서 터미널을 엽니다.

```bash
npm ci
npm run dev
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. macOS에서는 `SKCT LAB 시작.command`를 더블클릭해 서버와 브라우저를 함께 열 수도 있습니다. 터미널을 닫으면 서버가 종료됩니다. 로그인·유료 API·외부 폰트 없이 사용할 수 있습니다. 의존성 설치 후 로컬 서버 실행과 학습은 인터넷 없이 가능합니다. React/Vite 프로젝트이므로 `index.html` 더블클릭 대신 위 명령으로 실행합니다.

```bash
npm run check             # 수학·기능 테스트 + TypeScript 검사 + 프로덕션 빌드
npx playwright install chromium
npm run test:e2e          # 실제 브라우저 기능 / 모바일 검사
SKCT_STATIC_TEST=1 npm run test:e2e  # 빌드 자산을 라우팅하여 포트 없이 DOM 검사 (로컬 Chrome 필요)
npm run preview          # 빌드 결과 실행, http://127.0.0.1:4173
npm run review           # 유형마다 5문항 사람 검토용 샘플
```

## 사용

- **실전 모의고사:** 학습 홈에서 창의수리/수열추리 실전 시작. 20문항·15분. 시작 후 일시정지 불가. 제출한 답과 건너뛴 문항은 잠기며 이전 이동 불가. 만료 시 미응답 포함 자동 제출. 종료 후 전체 해설 공개.
- **카드 학습:** 보기 선택 시 타이머 자동 시작 → 정답 제출. 상단 시작 버튼으로 먼저 시작할 수도 있습니다. 일시정지 중 보기 선택은 학습을 재개합니다. 오답은 정답·정석 풀이·최단풀이·핵심 공식·최소 메모식·인식 신호 표시. 정답 자동 다음은 옵션. 시간 제한 해제와 일시정지 가능.
- **유형별 훈련:** 영역·난도·세부 유형·랜덤/약점/속도 선택. 전체 실전 기본 난도는 12 Medium + 8 Hard이며 Easy와 일부 단순 변환 유형은 신규 출제에서 제외합니다. 특정 유형 선택 시 해당 유형의 난도 적용.
- **메모장/계산기:** 같은 화면에서 사용. 문항별 메모 자동 저장, 삭제, 이전 세션 메모 복원. 괄호·소수·단항 음수 지원. eval 사용 없음.
- **오답노트:** 유형/난도 필터, 최근/반복 오답순, 개인 풀이법, 동일 문제 복습, 같은 유형 새 변형, JSON 다운로드. 45초 초과 정답은 속도 복습 대상으로 표시.
- **통계:** 첫 시도 기준 유형별 정답률·평균 시간, 영역별 정답률, 최근 점수 그래프, 날짜별 학습량. 같은 숫자·조건의 문항은 시드와 선지 순서가 달라도 재도전으로 따로 집계.
- **문제은행:** 신규 출제용 63개 유형(창의수리 50 / 수열추리 13) 검색·샘플·연습 및 즐겨찾기. 과거 111개 생성기는 저장 기록 검증용으로 보존합니다.
- **신고:** 이유·문항 스냅샷·ID·시드·생성기 버전을 로컬에 저장. 서버 전송하지 않음.
- **백업:** JSON 전체 내보내기/가져오기, CSV 기록 내보내기. 복원 전 현 기록 백업 다운로드. JSON 버전·문항·정답·세션·기록 구조 검사 및 첫 시도 표시 재계산. 기존 저장 기록의 표시를 교정할 때 원본은 `skct-lab:v1:before-migration`에 보존합니다. 잘못된 파일은 거절.

단축키: 1~5 선택 / Enter 제출 / N 다음 / M 메모 포커스 / C 계산기 포커스. 입력 요소·대화상자 안에서는 문제 단축키가 작동하지 않습니다.

모바일에서는 메뉴 버튼으로 문항 목록과 학습 메뉴를 열고, 문제 아래의 메모장·계산기를 사용하며, 하단의 바로가기 버튼으로 입력 도구에 즉시 이동할 수 있습니다. 라이트/다크 모드를 지원합니다.

## 정답 검증

111개 세부 유형(창의수리 86 / 수열 25), 유형당 200개 시드, **22,200개 생성 사례**를 자동 검사합니다. 조건 대입 검산은 생성 코드와 분리되어 있습니다. 경우의 수는 경우 열거, 최단경로는 DP, 수열은 모든 항의 규칙, 해설은 모든 표시 계산 단계를 별도 검사합니다. 선지 중복·정답 유일성·인덱스·단위·정수·확률 범위를 확인합니다. 런타임 검증 실패 문항은 제외합니다.

풀이 화면에서는 유형·난도·수열 규칙 힌트를 숨기고 채점 후 해설에서 공개합니다. 정답은 저장된 출제 규칙으로 검산하며, 유한 수열의 가능한 모든 연장 규칙에 대해 절대적 유일성을 보장하지 않습니다. 실전과 동일한 난도라는 보장도 없습니다. 자동 계산 통과는 자연어 검토 완료를 의미하지 않습니다. 사람 검토 절차와 추가 제한은 [문항 정책](docs/QUESTION_POLICY.md)을 확인하세요.

## 데이터 구조

- `src/engine/types.ts`: 문항·세션·기록·신고·백업 계약
- `src/engine/creative.ts`, `sequence.ts`: 결정적 시드 생성기
- `src/engine/verify.ts`: 생성기와 별도의 조건 검산 / 해설 검사
- `src/engine/bank.ts`: 검증된 생성기 등록·난도 균형·최근 문항 회피·약점 가중 출제
- `src/engine/session.ts`: 답안 잠금·채점·제출·첫시도 통계
- `src/engine/storage.ts`: 버전 1 JSON 저장·검사·백업·CSV
- `src/components`: 도구·통계·개발 전용 관리자
- `tests`: 수학 / 기능 단위 / Playwright 브라우저 테스트
- `.github/workflows/check.yml`: 테스트 → 브라우저 검사 → 빌드 → 조건부 Pages 배포

새 생성기는 공개 배열에 등록하기 전에 독립 검산·200시드·사람의 5문항 검토·PR 리뷰가 필요합니다. ID에 생성기 버전과 시드를 넣고 기록에는 전체 문항을 스냅샷으로 저장합니다. 향후 새 저장 버전은 원본을 보존하는 마이그레이션을 먼저 구현해야 합니다.

## GitHub Pages 배포

1. GitHub에 저장소를 만들고 **이 폴더 내용**을 올립니다. PDF·node_modules·개인 백업은 올리지 않습니다.
2. Settings → Pages → Source에서 **GitHub Actions**를 선택합니다.
3. main에 push합니다. 워크플로가 자동 검산·브라우저 테스트·빌드를 통과한 경우에만 배포합니다.
4. Settings → Branches/Rulesets에서 main PR 리뷰와 `verify` 상태 검사를 필수로 지정합니다.
5. `https://<사용자>.github.io/<저장소>/`로 접속합니다. Actions가 실제 저장소 이름으로 Vite base를 설정하므로 이름을 바꿔도 경로가 맞습니다. `<사용자>.github.io` 저장소는 `/`로 빌드합니다.

터미널에서 업로드하려면 새 GitHub 저장소 주소로 다음 명령을 실행합니다. 이 폴더는 `main` 브랜치로 Git 초기화되어 있습니다.

```bash
git add .
git commit -m "Build SKCT LAB"
git remote add origin https://github.com/<사용자>/<저장소>.git
git push -u origin main
```

GitHub Pages는 코드를 공개합니다. 관리자 컴포넌트는 개발 모드에서만 동적으로 포함되며 프로덕션 빌드에서는 제외됩니다. 원본 문제집·개인 학습 백업을 저장소에 넣지 마세요.

[Vite 배포 가이드](https://vite.dev/guide/static-deploy.html), [GitHub Pages Actions 가이드](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 참고했습니다.

Vercel을 사용하려면 Framework `Vite`, Build `npm run check`, Output `dist`, base `/`를 사용하세요. GitHub 저장소 보호 검사도 유지합니다. GitHub 저장소 업로드와 Pages 설정을 완료했습니다. 실제 배포 결과는 저장소 Actions에서 확인할 수 있습니다.

## 관리자와 향후 확장

`npm run dev`에서만 개발자 검토실이 나타납니다. 문항 초안 CRUD·난도/유형/정답/해설 수정, 수식·선지 검사, 사람 검토 승인 상태, 신고 확인, 초안 내보내기가 가능합니다. **로컬 승인만으로 임의 문항을 실전 문제은행에 공개하지 않습니다.** 등록된 생성기 수정은 테스트와 PR을 거칩니다.

초기 버전에는 서버 인증, 기기 간 동기화, AI API 생성, PDF 자동 수집, 서버 신고 전송, 실전 난도에 대한 외부 전문가 인증은 없습니다. 백엔드 연결 시 저장 어댑터를 Supabase로 대체하고 계정 소유권/RLS를 도입할 수 있도록 도메인 데이터와 UI를 분리했습니다.

localStorage는 사이트 주소·포트·브라우저마다 별도입니다. iCloud 폴더에 소스가 있어도 브라우저 학습 기록이 자동 동기화되지는 않습니다. 개발 서버와 배포 사이트 사이 기록 이동은 JSON 백업을 사용하세요. 저장 실패는 화면에서 알립니다. 20MB 이상 백업은 거절하며 장기 기록이 커지면 IndexedDB로 확장하는 것이 다음 단계입니다.
